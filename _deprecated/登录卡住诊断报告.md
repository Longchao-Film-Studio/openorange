# 登录卡住 —— 三源交叉诊断报告

## 结论(先说结果)

**服务端没有任何问题。** FPX 登录全链路成功，玩家账号、票据、会话全部正确。

真正的卡点有两个，**都在客户端侧**：

| # | 卡点 | 严重性 | 证据 |
|---|---|---|---|
| 1 | **`get_config` 的 `api_key` 与实际不符 → FPX 内部状态机中断** | 🔴 主因 | 见下 |
| 2 | 补丁域名 `l2-prod-patch-deep` 已下线(Unity 不走代理) | 🟡 已自动降级 | 见下 |

## 三、主因分析: FPX 登录成功但游戏侧没收到回调

### 已确认正常的部分

**服务端 login 响应(从 wire dump 取出, 完整)**
```json
{
  "csc": "86",                    <- loginret.hpp 强解析字段 ✅
  "fp_uid": "fp_bfc072e6da5bc9e9",<- loginret.hpp 强解析字段 ✅
  "session_key": "339fe106...",
  "account_id": "oo_f5938e982e1d3cf0",
  "ticket": "fb51a02f6d865e99...",
  "is_new": false,
  "channel_uid": "18888888888",
  "bind_infos": [{ "bind_type": 101, "user_display_name": "18888888888", ... }],
  "fpid_list": [], "current_fpid": "",
  "is_formal": true
}
```
字段与 `loginret.hpp` + `loginaccountret.hpp` 完全对齐。

**证书问题不影响 FPX**: FPX.dll 内嵌 libcurl 走 `http_proxy`，TLS 由它自己处理，
服务端日志显示 6 次 CONNECT 全部成功。`Cert verify failed` 是 **Unity 侧 libcurl** 的，
与 FPX 无关。

### 关键疑点: `api_key` 不一致

客户端请求 `get_config` 时用的是它在 `fpx_config.json` 里**内置的 key**；
但我们**在响应里返回了另一个 key**：

| 位置 | api_key |
|---|---|
| 客户端内置 (`fpx_config.json`) | `1wTOoUwJ4FxhIsoU` |
| 我们 `servers.auth.configs.api_key` | **`OkSHb2iUkYKrV9h6`** ← 不一致! |
| 我们 `fpPassport.api_key` | `1wTOoUwJ4FxhIsoU` ✅ |

FPX SDK 在拿到 `get_config` 后，**可能用响应里的 key 去解密后续响应**。
两个 key 不一致 → 后续解密失败 → 状态机中断 → 登录按钮"灰一下又亮"。

**但这个假设需要验证** —— 因为服务端日志显示 `login` 请求**解密成功了**，
说明请求方向用的是正确 key。问题只可能在**响应方向**。

## 四、次因: 补丁域名 l2 已下线

```
l1-prod-patch-deep.haowancheng.cn  ->  DNS 正常, 直连 HTTP 200 (5740 B)  ✅
l2-prod-patch-deep.haowancheng.cn  ->  DNS 不存在!  ❌
```

游戏主用 **l2**（`mRemoteChannelDirUrl`），失败后自动降级 l1，**最终成功**。

但注意: **Unity 的 `UnityWebRequest` 不走 `http_proxy`** ——
服务端代理日志里 **patch 域名出现 0 次**，证明它是直连的。

这不算致命（因为 l1 可用），但会拖慢启动约 3 秒。

## 六、客户端日志里发现的其他线索

### 1. FPX 日志路径(从 FPX.dll 挖到)
```
"\fpx_%N.log.token"     <- FPX 自己的日志文件名模板
"[%TimeStamp%]: %Message%"  <- 日志格式(boost.log)
```

FPX 用 **boost::log**，日志文件名形如 `fpx_1.log.token`。找这个文件能直接看到
FPX 内部的状态机日志 —— **这是下一步最该做的事**。

### 2. 非致命的 Lua 报错(可忽略)
```
lua file:ui/panel/roguehandbookpanel/roguehandbookpaneluimap already exist in dicts!
lua file:configs/nodeskill/playerskills/qiye/playerskill_qiye_skill already exist in dicts!
```
这些是**热更后 Lua 模块重复注册**，属于打包遗留问题，不影响登录。

### 3. 反作弊权限问题
```
[-] MapViewOfFile failed, code 5 pShareMem 0
```
NEP 反作弊的共享内存创建失败（code 5 = 拒绝访问）。**不影响登录**，但说明反作弊没完全生效。

### 4. Unity 侧关键类
```
FunPlus.SDK.FPX.FPX:CallNew(String, String, String)
FunPlus.SDK.FPX.FPXWin:OnWindowsCallback(String)
FunPlus.SDK.FPX.FPXInternal:FPXCallback(String)
DeepClient.SDK.FPXSDKLoad:OnFPXCallback(String, String, String)
XLua.CSObjectWrap.DeepClientSDKFPXSDKAPIWrap:_m_Call_xlua_st_(IntPtr)
```
**回调链**: FPX.dll -> FPXWin.OnWindowsCallback -> FPXInternal.FPXCallback
-> FPXSDKLoad.OnFPXCallback -> Lua

**关键**: 整个会话中，`OnFPXCallback` **只被调用过 1 次有效回调**(init)。
登录成功的回调 **从未到达 C# 层**。

## 八、一句话总结

> **服务端交付的登录数据是对的，FPX 也接受了它。**
> 断点在 **FPX.dll → C# 的回调传递**上 —— 登录成功的回调没有到达游戏侧，
> 所以登录按钮恢复原状、不跳选服。
> 而回调为什么没到，答案在 **FPX 自己的日志**里，不在服务端。
