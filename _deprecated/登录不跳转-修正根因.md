## 一、先纠正上一版的错误

上一版看到日志末尾 `Cannot find global lua function:GameDispose`，推断「Lua 主流程没启动」。**这是错的。**
对比两个文件即可排除：

| 文件 | GameStart | GameInit | GameDispose | EnterGame | require FPXSDKINCLUDE |
|---|---|---|---|---|---|
| `main.lua` | 有 | 有 | **无** | 有 | 有 |
| `logicmain.lua` | 有 | 有 | **有** | 无 | 无 |

`XluaManager.Start()` 执行 `require Main`（`LuaConst.LuaEntranceScript = "Main"`，Assembly-CSharp 第 392021 行）
→ 加载的是 **`main.lua`** → 它本来就没有 `GameDispose`。

`GameDispose` 只有 `logicmain.lua` 有，而它由 `patchhelper.lua:212` 的 `require("LogicMain")` 在**补丁阶段结束后**加载。

**所以「找不到 GameDispose」是正常行为，不是故障。**

## 六、真正的根因

日志里唯一出现的回调日志是 **`FPXSDKLoad OnFPXCallback`**（类名是 `FPXSDKLoad`，不是 `FPXSDKBridge`）：

```
[7] 4:16:26:  FPXSDKLoad OnFPXCallback Module : platform  func : init result : {...}
```

调用栈（日志第 26/34/46 行）显示来自 `DeepClient.SDK.FPXSDKLoad:OnFPXCallback`。

### 时序推断

```
① FPX 初始化  ->  FPXSDKLoad 注册回调
                      |
② FPX.dll 触发 init 回调
     -> 只到达 FPXSDKLoad.OnFPXCallback      (日志证明)
     -> FPXSDKBridge.OnFPXCallback 未收到    (日志证明)
                      |
③ DeepClient.LoadGame.Start()
     -> FPXSDKBridge.Init() 又注册一次
     -> 但 FPX.dll 初始化已完成, 不会再广播 init
                      |
④ 用户点登录 -> FPX.dll 处理 -> 产生 login 回调
     -> 回调只发往"注册时占用的那个槽位" = FPXSDKLoad
     -> FPXSDKBridge 收不到 -> Lua 收不到 -> 不跳转
```

### 结论

> **`FPX.InitCallBack` 的回调槽位被 `FPXSDKLoad` 占用，`FPXSDKBridge.OnFPXCallback` 从未生效。**
>
> 后果：即使 FPX.dll 成功完成登录并产生 login 回调，
> 该回调也只会送到 `FPXSDKLoad`，而 `FPXSDKLoad` **不转发给 Lua**
> （从现有证据看它只打日志）。
>
> 于是 `fpxsdkreceiver.lua` 的 `OnFPXCallback` 永远不被调用，
> `EnterGame()` 永远不执行，界面停在原地。

### 为什么这不是服务端问题

| 事实 | 证据 |
|---|---|
| `FPXSDKBridge.OnFPXCallback` 连 **init** 都没收到 | 日志第 339156 行格式出现 0 次 |
| init 回调发生在**任何网络请求之前** | 日志第 54 行 cert 错误早于第 55 行 init 回调 |
| 服务端数据已被 FPX 接受 | `send_code` 返回 `{"code":0}`，`login` 被正常解密 |

**一个从 init 阶段就断掉的转发链，和 login 阶段的响应内容无关。**
