# 登录不跳转 —— 最终结论

> 全部来自 `GameAssembly_clean.dll` 反汇编 + `Player.log` 行号。

---

## 一、我的三次误判（明确作废）

| # | 我说过 | 反证 | 判定 |
|---|---|---|---|
| 1 | `FPXSDKLoad` 抢占回调槽 | `InitSDK` 不注册回调 | 错 |
| 2 | `/api/login` 字段类型不对 | 那是登录面板自己的 HTTP，与 FPX 链路无关 | 错 |
| 3 | `platform` 是 `FPXCompat` 空壳 | 日志行 59/92 有 `FPXWin`/`FPCAPI` | 错 |

### 4.1 行 48 无日志是自洽的

`print` 证实会进日志（decompiled 66553-66579，注册于 67861-67862）：


## 五、决定性推论

行 56 与行 71 **两次** `FPXSDKAPI.Call` 都没产生 `FPCAPI:Call`。

```lua
-- fpxsdkapi.lua:55-59
local function wrap_func(...)
  if not CS_FPXSDKAPI.SdkIsInitialized then
    return              -- ★ 静默返回，无日志、无异常
  end
```

**这完美解释「无日志、无异常、无副作用」。**

反证排除「`platform` 为 null」：`InitSDK` 在 `GetPlatform()` 为 null 时抛异常
（`0x012CDB46  je 0x12CDB6E` → `0x2A0C80`），而 InitSDK 正常完成了。

## 六、反汇编证实的关键链路

### 6.1 `SdkIsInitialized` 的唯一赋值点

```csharp
// FPXSDKBridge.Init()   decompiled 行 335083-335089
public static void Init() {
    FPX.InitCallBack(new FPXCallback(OnFPXCallback));
    FPXSDKAPI.SdkIsInitialized = FPXSDKLoad.IsInitialized;   // ★ 唯一
}
```

```asm
FPXSDKBridge.Init  RVA 0xF5BCF0
  0x00F5BD8F  call FPX.InitCallBack
  0x00F5BD93  mov  rax, [0x02F65B00]        ; FPXSDKLoad 类
  0x00F5BD9A  mov  rcx, [0x02F658D8]        ; FPXSDKAPI 类
  0x00F5BDA1  mov  rdx, [rax + 0xb8]        ; 静态区
  0x00F5BDAF  movzx ebx, byte ptr [rdx]     ; 读 IsInitialized
  0x00F5BE24  mov  byte ptr [rcx + 8], bl   ; 写 SdkIsInitialized
  0x00F5BE30  ret
```

**无分支、无条件。** `SdkIsInitialized` == `FPXSDKLoad.IsInitialized`。

### 6.2 `FPXSDKLoad.IsInitialized` 地址 = `0x031EDA65`

```asm
FPXSDKLoad.OnFpxSdkInitialized  RVA 0x12CE7D0
  0x012CE807  cmp byte ptr [0x031EDA65], 0    ; ★ 读 IsInitialized
  0x012CE81C  jne 0x12ce83d                   ; if (IsInitialized) 跳过
  0x012CE836  mov byte ptr [0x031EDA65], 1    ; ★ IsInitialized = true
  0x012CE841  call FPXJson.Serialize
  0x012CE860  call FPXInternal.GetPlatform()
  0x012CE886  call 0x5c40                     ; platform.Call(...)
```

同族静态字段（`InitSDK` 写入）：`0x031EDA62`、`0x031EDA60`、`0x031EDA5C`、`0x031EDA5B`。

**`0x031EDA65` 只由 `OnFpxSdkInitialized` 写入。**

### 6.3 `FPXSDKLoad.Start(cb)` 把回调存到静态偏移 0x8

```asm
FPXSDKLoad.Start(Action<bool>)  RVA 0x12CE8B0
  0x012CE8DC  mov rdx, [rax + 0xb8]        ; 静态区
  0x012CE8E3  mov [rdx + 8], rbx          ; ★ OnCompletedCb = cb
  0x012CE908  jmp 0x12cd9b0               ; -> InitSDK()
```

```csharp
// dump.cs 14955
public static bool IsInitialized;          // 0x0  <- 0x031EDA65
private static Action<bool> OnCompletedCb; // 0x8  <- [静态区+8]
```

### 6.4 委托间接调用（静态扫描 0 caller 的原因）

全库扫描 `call 0x12CE8B0` / `0x12CD9B0` / `0x12CE7D0` / `0x12CDEA0`：**各 0 处**。

这不是「没被调用」，而是 **IL2CPP 委托机制**：

```asm
FPXInternal.Update()  RVA 0x12CC160
  0x012CC1C2  mov  r10, [rbx + 0x18]      ; 每轮重读 Callback
  0x012CC1E7  call qword ptr [r10 + 0x18] ; 间接调用
```

日志行 95-96 证明这条路径活着：

```
DeepClient.SDK.FPXSDKLoad:OnFPXCallback(String, String, String)
FunPlus.SDK.FPX.FPXInternal:Update()
```

### 6.5 `FPXSDKLoad.OnFPXCallback` 是入队函数

```asm
FPXSDKLoad.OnFPXCallback  RVA 0x12CDEA0
  0x012CDFA4  lea edx, [r15 + 6]           ; 6 元素
  0x012CDFAF  call 0x29feb0                ; il2cpp_array_new
  0x012CDFF9  lea rcx, [rbx + 0x20]        ; [0] = module
  0x012CE02C  mov [rbx + 0x28], r14        ; [1] = func
  0x012CE071  mov [rbx + 0x30], rax        ; [2]
  0x012CE0A8  mov [rbx + 0x38], rsi        ; [3] = result
```

与 `FPXInternal._cmdQueue`（`Queue<ValueTuple<string,string,string>>`）吻合。


## 七、结论

**能确定的：**

| # | 事实 | 证据 |
|---|---|---|
| 1 | `FPXWin`/`FPCAPI` 链路活的 | 日志 15 次 `FPCAPI` |
| 2 | `main.lua:13` 执行了 | 行 31597 栈含 `XluaManager:Start` |
| 3 | `GameStart()` 无异常返回 | 行 31716 |
| 4 | 走行 55-56 发 login | `patchconst.lua:3` + 无 else 分支痕迹 |
| 5 | **login 未到 `FPCAPI`** | 15 次 `FPCAPI` 全为 crash |
| 6 | `SdkIsInitialized` 只由 `FPXSDKBridge.Init` 赋值 | RVA 0xF5BCF0 |
| 7 | `IsInitialized`（`0x031EDA65`）只由 `OnFpxSdkInitialized` 写 | RVA 0x12CE7D0 |

**结论：**

> **`FPXSDKLoad.IsInitialized` 未被置 true
> → `SdkIsInitialized == false`
> → `fpxsdkapi.lua:57` 静默 return
> → login 从未发到原生层。**

## 八、证据边界（诚实交代）

**卡住的一环：`OnFpxSdkInitialized()` 有没有被调用？**

它**没有 `Debug.Log`**，调用与否在日志上完全无痕。
这是无法从日志判断它的**根本原因**，不是我没查。

静态分析的硬限制：

| 限制 | 说明 |
|---|---|
| 委托调用不可静态追踪 | `call qword ptr [r10+0x18]` 目标运行期才定 |
| `[0x02F65B00]` 是 MetadataUsage 运行期槽 | 静态拿不到类名 |
| `0x031EDA65` 是运行期静态存储 | 静态无法读其值 |

**要继续，只能用支持附加调试器的方式在运行时读 `0x031EDA65`。**
但用户明确禁止起游戏，所以到此为止。

## 九、对服务端的意义

**在验证第八节之前，不改服务端代码。**

若 `IsInitialized` 确为 false，那是客户端自身的初始化时序缺陷，
服务端无法直接修（不改客户端是硬约束）。届时必须回答：

> **为什么官方服务器在时 `IsInitialized` 能变成 true？**

这是一个**服务端可影响**的问题 —— 因为 `platform/init` 回调的 payload
由服务端与原生 SDK 交互产生。若官方返回的 payload 里有额外字段
驱动 `OnFpxSdkInitialized`，那这就是服务端该补的东西。
