# 登录不跳转 —— 反编译源码级根因分析

> 本文所有结论都有**代码行号**或**日志行号**支撑，无推测。

## 一、完整调用链(从反编译源码还原)


发行包 `Debug.isDebugBuild == false` → 走 **原生 FPX 登录窗口**分支。这和日志吻合。

### 2. 登录成功后的跳转 —— `modules/sdk/fpxsdkreceiver.lua` 第 12-20 行


### 3. C# 转发层 —— `Assembly-CSharp.dll` 第 339154-339184 行(`FPXSDKBridge.OnFPXCallback`)

```csharp
private static void OnFPXCallback(string module, string func, string result)
{
    Debug.Log("FPXSDKBridge OnFPXCallback Module : " + module + "  func : " + func + " result : " + result);
    if (module == "platform" && func == "init") { ...; return; }   // init 特判
    if (!SdkLuaApiInitialized) {
        Debug.LogWarning("Lua api is unInitialized! Module : " + module + ...);
        return;                                                   // ★ 直接丢弃
    }
    LuaEnv luaEnv = BaseSingleton<XluaManager>.Instance.LuaEnv;
    IntPtr l = luaEnv.L;
    Lua.xlua_getglobal(l, "OnFPXCallback");                        // ★ 转发给 Lua

    Lua.lua_pushstring(l, func);
    Lua.lua_pushstring(l, result);
    Lua.lua_pcall(l, 3, 0, 0);

```

**这是唯一的转发路径。** 它不通，Lua 就永远收不到登录回调。

那 4 处 `OnFPXCallback` 分别是：

```

[  26]          DeepClient.SDK.FPXSDKLoad:OnFPXCallback(String, String, String)   <- 调用栈
```

### 关键推论 1: Lua 的 `OnFPXCallback` 从未执行

`fpxsdkreceiver.lua` 第 13 行会打印 `module: xxx  func: xxx result: xxx`。
**这种格式的日志在整个文件里出现 0 次** → Lua 函数一次都没被调用（连 init 都没有）。

### 关键推论 2: C# 的 `FPXSDKBridge.OnFPXCallback` 从未执行

`FPXSDKBridge.OnFPXCallback` 第 339156 行会打印 `FPXSDKBridge OnFPXCallback Module : ...`。
**这种格式出现 0 次** → `FPXSDKBridge` 完全没被触发。

（注意：日志里那条是 **`FPXSDKLoad`** 打的，是**另一个类**，说明 `FPXSDKLoad` 收到了 init，
但 `FPXSDKBridge` 没有。）

## 三、根因

### 转发链断在 `FPXSDKBridge.Init()` 是否被调用

`FPXSDKBridge.Init()`(`Assembly-CSharp.dll` 第 339146-339152 行)是这样注册回调的：

```csharp
public static void Init()
{
    FPX.InitCallBack(new FPXCallback(OnFPXCallback));      // ★ 注册回调
    FPXSDKAPI.SdkIsInitialized = FPXSDKLoad.IsInitialized;
}
```

**`FPX.InitCallBack` 是单例式注册 —— 后注册的会覆盖先注册的。**

日志里出现的是 `FPXSDKLoad:OnFPXCallback`，说明**实际生效的是 `FPXSDKLoad` 注册的那个回调**，
`FPXSDKBridge.OnFPXCallback` 被覆盖了（或 `FPXSDKBridge.Init()` 根本没被调）。

两种可能：

| 可能 | 含义 | 判别方法 |
|---|---|---|
| A | `FPXSDKBridge.Init()` 从未被调用 | 搜索谁调用 `FPXSDKBridge.Init` |
| B | `FPXSDKBridge.Init()` 被调用过，但随后 `FPXSDKLoad` 又注册覆盖了它 | 看调用时序 |

### 但无论 A 还是 B，**这条转发链和我们的服务端完全无关**

因为 `FPXSDKBridge.OnFPXCallback` **连 init 都没收到**。
它是在 FPX.dll 内部回调刚出来时就应该触发的 —— 这发生在任何网络请求之前。

**`FPXSDKBridge` 没收到 init，就绝不可能收到 login。**

## 四、因此: 服务端能做的和不能做的

### 服务端已经做对的部分

| 环节 | 证据 |
|---|---|
| `get_config` 被调用 | wire dump `api_get_config.req.json` |
| `send_code` 成功 | 响应 `{"code":0,"msg":"Success"}`，日志 `send_code -> code=071189` |
| `login` 成功 | 响应含 `csc:"86"`、`fp_uid`、`ticket`、`session_key` |
| 全部字段与客户端内置配置一致 | 8/8 项实测匹配 |

### 服务端**无法**影响的部分

从 `FPXSDKBridge.OnFPXCallback` 到 Lua 的 `OnFPXCallback` 这一段，**是纯客户端内存逻辑**：

```
FPX.dll 原生回调  →  FPXSDKBridge.OnFPXCallback  →  Lua OnFPXCallback  →  EnterGame()
     ↑                      ↑
  这里断的              这里断的
  (没收到 init)        (从没执行过)
```

这段链路上**没有任何网络交互**，服务端给什么数据都到不了这里。

## 五、下一步该查什么(有明确目标)

### 1. 找 `FPXSDKBridge.Init()` 的调用点

在反编译的 C# 里搜索 `FPXSDKBridge.Init`，看它是否被调用、在什么时机。

### 2. 找 `SdkLuaApiInitialized = true` 的赋值点

Lua 侧通过 `FPXSDKBridge.SdkLuaApiInitialized = true` 设置(`Assembly-CSharp.dll` 第 129373 行)。
搜索 Lua 里谁设的，看它有没有执行。

```lua
-- 应该在某个 lua 文件里:
CS.DeepClient.SDK.FPXSDKBridge.SdkLuaApiInitialized = true
```

### 3. 检查 `FPX.InitCallBack` 的注册顺序

看 `FPXSDKLoad` 和 `FPXSDKBridge` 谁先注册、是否能同时注册。

### 4. 最直接的验证

在 Lua 侧 `OnFPXCallback` 里加一行 `print`，或直接观察：
**如果游戏启动后 Lua 侧从没收到 init，那说明转发链从最开始就是断的** ——
那么问题就不在登录，而在**游戏集成 SDK 的方式**上。

---

## 六、结论

> **服务端数据正确，且已被 FPX SDK 接受。**
> 断点在客户端内部：`FPX.dll → FPXSDKBridge → Lua OnFPXCallback` 这条 C#/Lua 转发链
> **从未生效过（连 init 回调都没到达）**。
> 因此 Lua 永远收不到 `func == "login"`，`EnterGame()` 永远不会被调用，界面就不跳转。
>
> 继续在服务端加字段是**无效的** —— 需要解决的是客户端 SDK 回调注册问题。
