> 全部结论来自 `GameAssembly_clean.dll` 实际反汇编 + 客户端 Player.log。
> 每条都附 RVA / 行号。

## 一、决定性发现：平台层有"空壳实现"

`IFPXPlatform` 有 3 个实现类（`dump.cs` 646159 / 646189 / 646216）：

| 类 | `Call()` RVA | 反汇编 bytes | 行为 |
|---|---|---|---|
| **`FPXCompat`** | **`0x5ECA20`** | `c20000` | **`ret 0` —— 空方法** |
| **`FPXDefault`** | **`0x5ECA20`** | `c20000` | **`ret 0` —— 空方法** |
| `FPXWin` | `0x12CF740` | `e969e3fbff` | `jmp 0x128dac0` —— 真正转发 |

```asm
; ---- FPXCompat.Call / FPXDefault.Call / SetGameObjectName ----
; RVA 0x5ECA20  (全长 3 字节)
0x005ECA20  c20000                    ret 0

; ---- FPXCompat.CallBool ----
; RVA 0x5E74D0
0x005E74D0  b001                      mov al, 1
0x005E74D2  c3                        ret        ; 永远返回 true

; ---- FPXWin.Call (真正的实现) ----
; RVA 0x12CF740
0x012CF740  498bc1                    mov rax, r9
0x012CF743  4d8bd0                    mov r10, r8
0x012CF746  488bca                    mov rcx, rdx
0x012CF74C  498bd2                    mov rdx, r10
0x012CF752  e969e3fbff                jmp 0x128dac0
```

**`FPXCompat.CallBool` 永远返回 `true`** —— 典型"假装成功"的兼容层。

## 四、决定性推理：为什么断定是"空方法"

`main.lua` 的执行顺序：

```lua
13: CS.PlatformService.InitPlatform()              -- ✅ 日志行31607 有
...
39: FPXSDKAPI.Call(FPXModule.CRASH, ..., crashExtraData)   -- ✗ 无任何痕迹
41: local go = CS.UnityEngine.GameObject.Find(...)
48: print("not find Timeline/...")                -- ✗ 0 次
```

行 13 有日志、行 48 无日志，中间只隔着行 39 的调用。

`fpxsdkapi.lua:63-65` 给调用包了 `xpcall`：

```lua
xpcall(function() return func(unpack(args)) end, __handle_error)
-- __handle_error 会 CSDebug.LogError
```

**异常会被 `LogError` 记录下来。而日志里 `LogError` 也没有。**

> 所以既不是异常，也不是早退。
> **只能是"调用成功返回了，但什么都没做"** —— 即 `ret 0`。

## 五、结论

> **`FPXInternal.GetPlatform()` 返回的是 `FPXCompat`（或 `FPXDefault`）空壳，不是 `FPXWin`。**
>
> 这两个类的 `Call()` 都是 `ret 0`。于是：
>
> **所有** `FPXSDKAPI.Call(...)`（login / crash / tracking / exit）
> **全部静默失效** —— 无日志、无异常、无副作用。
>
> → `FPCWindows.Login` 从不执行
> → `FPX_Login()` 从不执行 → 原生登录窗从不打开
> → 永远没有 login 回调
> → `fpxsdkreceiver.lua:19` 的 `EnterGame()` 永不执行
> → **永久停在登录界面。**

## 六、这解释了全部现象

| 现象 | 原因 |
|---|---|
| 登录界面正常显示 | UI 层不依赖 SDK |
| 能点"获取验证码" | 那是 UGUI 面板，直接 HTTP 到 fp-passport |
| `/api/login` 返回 200 | 面板自己的请求，与 FPX 回调链无关 |
| 无任何 FPX 登录回调 | `platform.Call` 是空方法 |
| 无任何 Lua print | `main.lua` 在行 39 之后的行都没执行 |
| 无报错 | 空方法不抛异常 |

**关键认知修正：** `/api/login` 被调用 ≠ 登录流程在走。
那是 **UGUI 登录面板自己发的 HTTP**，和 FPX 回调链是**两条独立的路**。

## 七、诚实交代：我没做到的最后一步

`GetPlatform` 里 `0x012CC0A4  mov rcx, [0x02F73628]` 取的类型句柄，
在二进制里是 **IL2CPP MetadataUsage 运行期槽**（实测值 `0x000001F28AC13F60`），
由 `il2cpp_init` 在运行时填充，**静态无法反查类名**。

所以：

- ✅ 能确定：**拿到的是空实现**（日志静默 + 3 个实现的 `Call` 地址反证）
- ❌ 不能确定：**具体 new 的是哪个类**（需要运行时）

这一步卡在 IL2CPP 的静态限制上，不是我没查。
