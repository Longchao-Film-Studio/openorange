### 3.1 行 48 无日志是自洽的

`print` 已证实会进日志：

```csharp
// StaticLuaCallbacks.Print  decompiled 行 66553-66579

// 注册: LuaEnv() 行 67861-67862

```

行 42-49 是 if/else 必走其一：

- 走行 45（`go` 与 `timeline` 都非 nil）→ 无日志，**与观测一致**
- 走行 48（任一为 nil）→ 必有日志，**与观测矛盾**

**所以走的是行 45。`GameStart()` 确实跑完了。**

## 四、决定性结论

行 56 和行 71 **两次** `FPXSDKAPI.Call` 都没有产生 `FPCAPI:Call`。

两个候选：

### 候选 A：`SdkIsInitialized` 为 false → 静默 return

```lua
-- fpxsdkapi.lua:55-59
local function wrap_func(...)
  if not CS_FPXSDKAPI.SdkIsInitialized then
    return              -- ★ 静默返回，无日志
  end
```

这**完美解释**了「无日志、无异常、无副作用」。

### 候选 B：`platform` 为 null → `CallNew` 静默返回

已被推翻：`FPXWin`/`FPCAPI` 在日志里活着，且 `InitSDK` 在 `GetPlatform()` 返回 null 时会抛异常
（`0x012CDB46  je 0x12CDB6E` → `0x2A0C80` throw），而 InitSDK 正常完成了。

**所以是候选 A。**

## 五、为什么 `SdkIsInitialized` 会是 false

赋值只有一处：

```csharp
// FPXSDKBridge.Init()   decompiled 行 335083-335089
public static void Init() {
    FPX.InitCallBack(new FPXCallback(OnFPXCallback));
    FPXSDKAPI.SdkIsInitialized = FPXSDKLoad.IsInitialized;   // ★ 唯一赋值点
}
```

调用者只有 `LoadGame.Start()`（行 333458），它在日志行 2960 执行、行 27218 完成。

反汇编确认赋值是无条件直传：

```asm
FPXSDKBridge.Init  RVA 0xF5BCF0
  0x00F5BD8F  call FPX.InitCallBack
  0x00F5BD93  mov  rax, [0x02F65B00]        ; FPXSDKLoad 类
  0x00F5BD9A  mov  rcx, [0x02F658D8]        ; FPXSDKAPI 类
  0x00F5BDA1  mov  rdx, [rax + 0xb8]        ; 静态区
  0x00F5BDAF  movzx ebx, byte ptr [rdx]     ; 读 IsInitialized
  0x00F5BE24  mov  byte ptr [rcx + 8], bl   ; 写 SdkIsInitialized
  0x00F5BE30  ret
```

**无分支、无条件。** 所以 `SdkIsInitialized` 的值 = `FPXSDKLoad.IsInitialized` 的值。

## 六、还没闭合的最后一环

`FPXSDKLoad.IsInitialized` 何时被置 true？

- 日志行 74 `FPX sdk initialize result : 1 .` 说明 `init` 回调的 code==1
- 但**没有**日志能直接证明 `FPXSDKLoad.IsInitialized` 这个静态字段被写成 true

`FPXSDKLoad` 字段（dump.cs 14955）：

```csharp
public static bool IsInitialized; // 0x0
```

和 `OnFpxSdkInitialized` (RVA `0x12CE7D0`)，确认 `IsInitialized` 的写入点与条件。

## 七、如果确认是这个原因，服务端能做什么

关键约束：**不改客户端**。

若 `IsInitialized` 确实没被置 true，那这是**客户端自身的时序缺陷**，
服务端无法直接修复 —— 但可以验证一个替代路径：

| 路径 | 说明 |
|---|---|
| 官方原版能进 = 官方服务器行为不同 | 需要找出官方服务器让 `IsInitialized` 成立的差异点 |
| `platform/init` 回调的 `code` 语义 | 若官方返回的 payload 里有额外字段驱动 `IsInitialized` |

**结论：在确认 `IsInitialized` 写入点之前，不该再动服务端代码。**
