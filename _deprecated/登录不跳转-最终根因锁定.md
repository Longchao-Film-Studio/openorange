## 三、闸门 A 已排除（反汇编证明）

`FPXSDKBridge.Init` RVA `0xF5BCF0`：

```asm
0x00F5BD8E  call FPX.InitCallBack               ; 注册回调
0x00F5BD93  mov  rax, [0x02F65B00]              ; FPXSDKLoad 类
0x00F5BD9A  mov  rcx, [0x02F658D8]              ; FPXSDKAPI 类
0x00F5BDA1  mov  rdx, [rax + 0xb8]              ; FPXSDKLoad 静态区
0x00F5BDAF  movzx ebx, byte ptr [rdx]           ; ★ 读 IsInitialized
0x00F5BE24  mov  byte ptr [rcx + 8], bl         ; ★ 写 SdkIsInitialized
0x00F5BE30  ret
```

**与源码完全一致**（decompiled 335087-335088）：

```csharp
public static void Init() {
    FPX.InitCallBack(new FPXCallback(OnFPXCallback));
    FPXSDKAPI.SdkIsInitialized = FPXSDKLoad.IsInitialized;
}
```

无条件执行、无分支。而日志行 74 `FPX sdk initialize result : 1 .` 证明
`FPXSDKLoad.IsInitialized == true`。

**⇒ `SdkIsInitialized == true`。闸门 A 排除。**

## 四、闸门 B 是嫌疑点

`FPXInternal.GetPlatform` RVA `0x12CBF20` 反汇编（关键段）：

```asm
0x012CC030  mov  rdi, [rax + 0x10]        ; 读 platform 静态字段
0x012CC09B  call UnityEngine.Object.op_Equality
0x012CC0A2  je   0x12cc0f7                ; platform != null -> 跳走
0x012CC0A4  ...                           ; platform == null 分支:
0x012CC0AB  call 0x2A0C10                 ; 创建对象
0x012CC0C9  call GameObject..ctor          ; ★ new GameObject(...)
0x012CC0DF  mov  [rcx], rbx                ; 存入 platform
0x012CC10D  call UnityEngine.Object.get_name
0x012CC12B  call 0x2E80                    ; ★ 虚调用
0x012CC148  mov  rax, [rax + 0x10]         ; 返回 platform
0x012CC150  ret
```

**`GetPlatform()` 会自己 `new GameObject(...)` 惰性创建平台对象。**
若该 GameObject 上的组件类型缺失（脚本丢失），`platform` 仍为 null，
`CallNew` 就在 `0x012CFBBF` 静默返回 —— **不报错、不打日志**。

## 六、结论

> **`FPXInternal.GetPlatform()` 返回 null。**
>
> 于是 `FPX.CallNew` 在 `0x012CFBBF` 直接返回，
> **所有** `FPXSDKAPI.Call` 全部静默失效（包括 login / crash / tracking）。
> → `FPCWindows.Login` 未被调用 → `FPX_Login()` 未执行
> → 原生登录窗未打开 → 无 login 回调
> → `fpxsdkreceiver.lua:19` 的 `EnterGame()` 永不执行
> → **卡在登录界面。**

### 为什么这解释了「客户端日志一个 print 都没有」

`main.lua:48` 的 print 在 `FPXSDKAPI.Call`(行39) **之后**。
若行 39 抛异常，行 48 就不会执行 —— 但 Lua 的 `__genericCall` 包了 `xpcall`
（fpxsdkapi.lua:63-65），异常会被 `__handle_error` 吞掉并 `LogError`。
而日志里 `LogError` 也没有。**所以不是异常，是静默返回。**

这与闸门 B 的行为（`je 0x12CFBF2` 直接 ret，无日志）**唯一吻合**。
