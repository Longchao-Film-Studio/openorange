# 登录不跳转 —— 根因与证据（终结）

> 全部来自 `GameAssembly_clean.dll` 实际反汇编 + 22 个客户端日志。

---

## 一、我三次结论的更正

| 次 | 我说过 | 判定 |
|---|---|---|
| 1 | `FPXSDKLoad` 抢占了回调槽 | ❌ **错**，它不注册回调 |
| 2 | `/api/login` 字段类型不对 | ❌ **不是根因**，已按官方改对，仍卡 |
| 3 | 平台对象是空实现 `FPXCompat` | ✅ 反汇编实证 |

---

## 二、决定性发现：平台层有两个实现，一个是空壳

`IFPXPlatform` 有 3 个实现类；`Call()` 的地址完全不同：

| 类 | `Call()` RVA | 反汇编 | 行为 |
|---|---|---|---|
| **`FPXCompat`** | **`0x5ECA20`** | `c20000  ret 0` | **空方法，什么都不做** |
| `FPXDefault`** | `0x5ECA20` | `c20000  ret 0` | 同样空 |
| `FPXWin` | `0x12CF740` | `jmp 0x128dac0` | 真正转发到 FPC 层 |

```asm
; FPXCompat.Call —— RVA 0x5ECA20   （全长 3 字节）
0x005ECA20  c20000              ret 0

; FPXCompat.CallBool —— RVA 0x5E74D0
0x005E74D0  b001                mov al, 1
0x005E74D2  c3                  ret      ; 永远返回 true

; FPXWin.Call —— RVA 0x12CF740  （真正的实现）
0x012CF740  498bc1              mov rax, r9
0x012CF746  488bca              mov rcx, rdx
0x012CF752  e969e3fbff          jmp 0x128dac0
```

注意 `CallBool` **永远返回 true** —— "假装成功"的典型兼容层写法。

## 三、失败链路（每个 RVA 都已反汇编）

```
main.lua:56   FPXSDKAPI.Call(FPXModule.PLATFORM, FPXFunc.LOGIN, nil)
  │
  ├─ fpxsdkapi.lua:57   if not SdkIsInitialized then return
  │                     ↑ 已排除：FPXSDKLoad.IsInitialized = true (日志行74)
  ├─ FPXSDKAPI.Call()   if (!SdkIsInitialized) {LogWarning; return;}
  │                     ↑ 已排除：日志里该警告 0 次
  │
  ├─ FPX.CallNew()      RVA 0x12CFB60
  │    0x012CFBB7  call FPXInternal.GetPlatform()
  │    0x012CFBBC  test rax, rax
  │    0x012CFBBF  je   0x12CFBF2      ← null 则静默返回
  │    0x012CFBDD  call 0x5C40          platform.Call(...) 虚调用
  │
  ├─ platform == FPXWin    → 0x12CF740 → jmp 0x128dac0 → FPCWindows.Login → FPX_Login
  └─ platform == FPXCompat → 0x5ECA20  → ret 0   ← 什么都不做
```

### 决定性的"静默"

`main.lua:13` 的 `PlatformService.InitPlatform()` **执行了**（行 31607）；

## 五、结论

> **`FPXInternal.GetPlatform()` 拿到的是空实现（`FPXCompat`/`FPXDefault`），不是 `FPXWin`。**
>
> 这两个类的 `Call()` 都是 `ret 0`。
>
> 所以**所有** `FPXSDKAPI.Call(...)` —— login / crash / tracking / exit ——
> **全部静默失效**：无日志、无异常、无副作用。
>
> → `FPCWindows.Login` 未被调用
> → `FPX_Login()` 未执行 → 原生登录窗未打开
> → 无 login 回调 → `fpxsdkreceiver.lua:19` 的 `EnterGame()` 永不执行
> → **永久卡在登录界面。**

## 六、这解释了全部现象

| 现象 | 原因 |
|---|---|
| 登录界面正常显示 | UI 不依赖 SDK |
| 能点"获取验证码" | 那是 UGUI 面板，直接 HTTP 到 fp-passport |
| `/api/login` 返回 200 | 面板自己的请求，与 FPX 回调链无关 |
| 没有任何 FPX 登录回调 | `platform.Call` 是空方法 |
| 没有任何 Lua print | `main.lua` 在 `Call` 之后的行都没执行 |
| 没有报错 | 空方法不抛异常 |

## 七、边界说明（诚实交代）

我**没有**做到的最后一步：

`GetPlatform` 里 `0x012CC0A4  mov rcx, [0x02F73628]` 取的类型句柄，
在二进制里是 **IL2CPP MetadataUsage 运行期槽**（实测值 `0x000001F28AC13F60`），
由 `il2cpp_init` 在运行时填充，**静态无法反查类名**。

所以我能确定的是"**它拿到的是空实现**"（由日志静默 + 三个实现的 `Call` 地址反证），
但"**具体 new 的是哪一个类**"需要运行时确认。
