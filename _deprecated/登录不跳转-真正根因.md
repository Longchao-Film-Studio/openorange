# 登录不跳转 —— 真正根因(官方数据对照确认)

## 一、发现官方真实响应样本

在启动器配置里找到了**官方服务器成功登录后的响应缓存**：

```
F:/haowancheng/GuiLongchao/prefs/deep_cn_setting.ini
  [fun__settings]
  cache_account_infos=<base64>
```

base64 解码后是官方 `/api/login`(或 session_login) 返回的完整 JSON。
**这是第一次拿到官方真实响应, 可以逐字段对照。**

## 二、逐字段对照结果

| 字段 | 官方值 | 我们返回 | 判定 |
|---|---|---|---|
| `fp_uid` | `35931389584` **(数字)** | `"fp_bfc072e6da5bc9e9"` (字符串) | **类型错** |
| `channel_uid` | `35931389584` **(数字)** | `"18888888888"` (字符串) | **类型错** |

| `msg` | (无此字段) | `"Success"` | 多余 |

## 三、FPX 期望的类型 —— 来自 FPX.dll 的硬证据

### 3.1 `loginaccountret.hpp` 字段表(按声明顺序)

从 `FPX.dll` 字节流直接挖出(结构头路径前 450 字节即字段名表)：

```
fp_uid | session_key | is_new | fp_device_id | msg | account_create_ts |
channel_uid | account_id | fpid_list | current_fpid | ticket |
delete_time_left | is_formal
```

### 3.2 解析方式：boost::json + to_number

同一段字节里紧接着出现：

```
D:\boost\x64_mt_lib\include\boost-1_81\boost/json/detail/value_to.hpp
value_to_impl
tag_invoke
...
FPX_JsonToObj
D:\Jenkins\...\common\FPXUtil.h
to_number            <<< FPX 自己的数字转换函数
```

`FPX.dll` 里存在这些错误串：

```
not a number
token is not a number
```

**说明: 这些字段走 `boost::json::value_to<T>` 的数字路径,
传字符串会直接解析失败。**

### 3.3 强解析标记

`loginret.hpp` 的两个字段带 `"xxx json value result:"` 调试标记(缺失即报错)：

```
csc json value result:
fp_uid json value result:
```

**`fp_uid` 是强解析字段 —— 类型不对必然失败。**

## 四、为什么这解释了所有现象

| 现象 | 解释 |
|---|---|
| `send_code` 正常 | 请求只有 mobile/code_type, 响应只有 code/msg, 无类型问题 |
| `/api/login` 服务端 HTTP 200 | TCP/加密层没问题 |
| `OnVerifyCodeLoginRet` **0 次** | FPX 反序列化 `loginaccountret` 失败, 不产生回调 |
| `FPX Login success` **0 次** | 同上 |
| 界面停在原地 | 回调没来, Lua 的 `EnterGame()` 不执行 |
| **官方服能进** | 官方返回的数字型 `fp_uid`, 类型正确 |

## 六、修复方案(纯服务端, 不改客户端)

### 6.1 `shared/models.py` 的 `login()` 返回值

```python
return {
    # --- loginaccountret.hpp (顺序一致) ---
    "fp_uid":            numeric_fp_uid,      # 数字! 不是 "fp_xxx"
    "session_key":       session_key,
    "is_new":            is_new,
    "fp_device_id":      "",
    "msg":               "Success",
    "account_create_ts": created_ts * 1000,   # 毫秒!
    "channel_uid":       numeric_channel_uid, # 数字!
    "account_id":        account_id,
    "fpid_list":         [],
    "current_fpid":      0,                   # 数字, 不是 ""
    "ticket":            ticket,
    "delete_time_left":  0,
    "is_formal":         False,
    # --- loginret.hpp ---
    "csc":               DEFAULT_CSC,
    "bind_infos":        json_string,         # JSON 字符串, 不是数组!
    # ...
}
```

### 6.2 `fp_uid` 与 `channel_uid` 改为数字

官方 `fp_uid == channel_uid == 35931389584`(同一个数字)。
我们应生成一个稳定的纯数字 UID(如手机号本身或派生数字)。

### 6.3 `bind_infos` 改为 JSON 字符串

官方:

```json
"[{\"bind_type\":101,\"bind_display_name\":\"18***70\",
   \"bind_info\":{\"id\":\"18***70\",\"name\":\"86\",\"email\":\"\"}}]"
```

注意 `bind_info` 是**非空对象**, 含 `id` / `name` / `email`。

### 6.4 `account_create_ts` 用毫秒

官方 `1726051819000` = 2024-09-11, 是**毫秒**时间戳。
我们用 `1789240656`(秒) —— 差 1000 倍。
