## 三、那登录窗口为什么还是弹出来了?

因为**你看到的登录界面根本不是游戏 Lua 画的**。`fpxuguipanel.lua` 第 40 行:

```lua
_panel_go = CS.Core.ResourceManager.Inst:Load(
    "ui/panels/SdkLoginPanel/SdkLoginPanel", CS.Core.EResourceType.Prefab)
```

它加载的只是**背景面板**。真正的手机号+验证码输入框是 **FPX.dll 的原生窗口**
（还记得那 26 个 `FpxUIShow*` 导出函数吗）。

所以在主流程没跑起来的情况下，你**仍然能看到并用那个原生登录窗口** ——
它自己直接发 HTTP 请求到 `fp-passport`（所以我们服务端收到了 `send_code`、`login`）。

**但「登录成功后跳转」这个动作是 Lua 的职责**（`fpxsdkreceiver.lua:19` 的 `EnterGame()`），
Lua 主流程没起来 → 没人接这个回调 → 界面永远停在原地。

## 四、为什么 Lua 主流程没起来 —— 关键在 `SetInitGame`

`fpxsdkreceiver.lua` 第 12-20 行:

```lua
function OnFPXCallback(module, func, result)
  Debug.Log("module: " .. module .. "  func: " .. func .. " result: " .. result)  -- 第13行
  if module == FPXModule.PLATFORM and func == FPXFunc.LOGIN then
    local result_t = json.decode(result)
    FPXAccount.onSdkLogin(__init_game, result_t)
    if not __init_game and not __enter_game and result_t.code == 1 then
      __enter_game = true
      EnterGame()          -- ★ 跳转
    end
  end
```

关键变量 `__init_game`（第 5-10 行，默认 `false`）由 `patchhelper.lua:216` 设为 `true`:

```lua
function PatchHelper.bindLogicFuns()
  require("LogicMain")
  require("CS")
  LuaHelper.BindGameTickFunc()
  print("BindGameTickFunc ok")
  FPXSDKReceiver.SetInitGame(true)     -- ★ 只有跑过这里, __init_game 才为 true
end
```

**注意这个语义**:

| `__init_game` | 含义 | 登录成功时 `OnFPXCallback` 的行为 |
|---|---|---|
| `false` | SDK 登录发生在**游戏逻辑启动前** | 走进 `EnterGame()` 跳转 |
| `true` | 游戏逻辑**已经启动**，登录是中途切换账号 | 只 `postEvent(ESdkLogin)`，不调 `EnterGame()` |

设计意图是: **冷启动时用 FPX 原生窗登录 → 成功后进游戏**。

日志显示 `BindGameTickFunc ok` 为 0 → `bindLogicFuns()` 没跑 → `__init_game` 保持 `false`
→ **就算回调到了 Lua，也会走 `EnterGame()` 分支**。

**所以 `__init_game` 不是障碍。真正的障碍是回调压根没到 Lua。**

## 五、回调为什么没到 Lua —— C# 侧代码

`Assembly-CSharp.dll` 第 339154-339184 行(`FPXSDKBridge`):

```csharp
private static void OnFPXCallback(string module, string func, string result)
{
    Debug.Log("FPXSDKBridge OnFPXCallback Module : " + module + ...);   // 第339156行
    if (module=="platform" && func=="init") { ...; return; }
    if (!SdkLuaApiInitialized) {
        Debug.LogWarning("Lua api is unInitialized! ...");            // 第339164行
        return;
    }
    ...
    Lua.xlua_getglobal(l, "OnFPXCallback");                           // 第339170行
    Lua.lua_pcall(l, 3, 0, 0);
}
```

日志中的精确统计:

```
"FPXSDKBridge OnFPXCallback"    x0     <-- 第339156行的日志, 从未打印
"Lua api is unInitialized"      x0     <-- 第339164行的日志, 从未打印
"module: ... func: ... result:" x0     <-- lua 第13行的日志, 从未打印
```

### 两个 x0 说明什么

第 339156 行的 `Debug.Log` 是**函数第一条语句**。它的输出为 0 意味着:

> **`FPXSDKBridge.OnFPXCallback` 这个委托从来没有被 FPX.dll 调用过 —— 连 init 都没有。**

而第 339164 行的 Warning 也是 0，排除了「进了函数但 `SdkLuaApiInitialized=false` 被拦」的可能。

### 那么 `SdkLuaApiInitialized` 是什么时候设为 true 的

`fpxsdkinclude.lua` 第 6-7 行(整个文件只有 7 行):

```lua
FPXSDKBridge = CS.DeepClient.SDK.FPXSDKBridge
FPXSDKBridge.SdkLuaApiInitialized = true
```

而 `fpxsdkinclude.lua` 由 `main.lua` 第 7 行 `require("Modules.SDK.FPXSDKINCLUDE")` 加载。

**`main.lua` 是被 `PatchHelper.exitPatchStage()` → `GameStart()` 触发的**
（见 `patchhelper.lua:223`），而它没跑。

## 六、结论

### 根因

> **客户端 Lua 主流程从未启动。**
>
> `PatchPhaseMgr` 的收尾 → `exitPatchStage()` → `bindLogicFuns()` → `GameStart()`
> 这条链**一次都没执行**，证据是链上每一个 `print` 在日志里都是 0 次，
> 以及退出时 `Cannot find global lua function:GameDispose`。
>
> 结果: `OnFPXCallback` 这个 Lua 全局函数从没被注册，
> 服务端返回的登录成功数据**没有任何代码去接收**，界面自然不跳转。

### 与服务端的关系

| 项 | 状态 |
|---|---|
| `/api/get_config` | 正确，8/8 字段与客户端内置值一致 |
| `/api/send_code` | 正确，返回 `{"code":0}` |
| `/api/login` | 正确，返回完整 loginret 字段 |
| **服务端能否解决跳转问题** | **不能** |

因为断点在「Lua 主流程是否启动」这一步，它发生在**任何网络请求之前**，
与 `fp-passport` 的响应内容无关。

### 为什么补丁流程走完了，Lua 主流程却没走

日志显示两套补丁系统:

| 系统 | 实现 | 日志表现 |
|---|---|---|
| `HybridLoadMgr` | **C# 侧**(热更 DLL 加载器) | `StartPatch.1~4`、`LoadSuccess` **全部成功** |
| `PatchPhaseMgr` | **Lua 侧**(游戏业务补丁) | **一次都没出现** |

`HybridLoadMgr` 只负责把 **dll + lua 字节码**加载进内存；
`PatchPhaseMgr` 才是**执行 Lua 主流程**的那一层。

`HybridLoadMgr` 完成(`LoadSuccess`) → 应该交棒给 Lua → **但接棒动作没发生**。

搜 C# 里谁在 `HybridLoadMgr` 完成后调用 Lua 的 `GameStart` / `GameInit`。

（日志里能看到 `Login.bytes`、`Bin.bytes`、`Base.bytes` 等被拷贝）。
