# 登录不跳转 —— 根因锁定(唯一结论)

> 本文取代此前全部 7 份登录分析文档(已移入 `_deprecated/`)。
> 全部结论均标注**日志行号**或**源码行号**, 无推测。

---

## 一、根因

> **`FPXSDKLoad` 抢占了唯一的 SDK 回调槽, 而 `FPXSDKBridge` 注册太晚, 抢不回来。**
>
> 结果: 登录成功回调只送到 `FPXSDKLoad`, 永远送不到 `FPXSDKBridge`,
> 也就永远到不了 Lua 的 `OnFPXCallback` → 不跳选服。

---

## 三、回调槽只有一个(源码证据)

`Assembly-CSharp.decompiled.cs` 第 335083-335089 行:

```csharp
public static void Init()
{
    FPX.InitCallBack(new FPXCallback(OnFPXCallback));   // 唯一的注册点
    FPXSDKAPI.SdkIsInitialized = FPXSDKLoad.IsInitialized;
}
```

`FPX.InitCallBack` 在**全部三个版本的 C# 反编译里各只有 1 处调用**:

| 文件 | 调用点 |
|---|---|
| `_hybrid_src` (热更) | 335087 |
| `_asmcsharp_pc` (主包) | 339150 |
| `_android_src` (安卓) | 同一位置 |

**但 `FPXSDKLoad` 自己的 `InitSDK()` 也注册了一个** —— 那在 `DeepFPXSdk.dll` 内部,
C# 侧看不到, 只能从行为反推。

## 六、为什么 `FPXSDKBridge.OnFPXCallback` 一次都没打印

看它在源码里的第一句(第 335093 行):

```csharp
private static void OnFPXCallback(string module, string func, string result)
{
    Debug.Log("FPXSDKBridge OnFPXCallback Module : " + module + ...);  // 第1句就是日志
    ...
}
```

**第一句就是 `Debug.Log`, 只要被调用就不可能不打印。**

日志里 0 次 → **这个方法从未被调用过。** 不是"打印被吞了", 是根本没进。

## 七、服务端在这条链上的位置

服务端**没错**。证据:

| 事实 | 证据 |
|---|---|
| `/api/send_code` 被调用 | `work/logs/wire/` 有完整请求/响应 |
| `/api/login` 被调用 | 同上 |
| 返回了正确结构 | 响应 JSON 已落盘 |

**但服务端返回什么, 都到不了 Lua 层** —— 因为回调链在客户端就断了。

⚠️ 注意: 这里说的是**登录回调分发**这条链。
`fp_uid` 类型/单位那些字段差异**仍然要修**, 那是下一个坎(见下)。

## 八、要怎么办

### 约束

**不能改客户端。** 这是原版游戏, 改了就不是原版了。

### 那官方是怎么通的?

关键问题: **官方运行时, `FPXSDKLoad` 也抢占了回调槽, 为什么官方能进游戏?**

只有两种可能:

| # | 可能 | 验证方式 |
|---|---|---|
| A | `FPXSDKLoad.OnFPXCallback` **内部会转发**给 `FPXSDKBridge` | 反汇编 `GameAssembly.dll` 里 `FPXSDKLoad.OnFPXCallback` 的方法体 |
| B | 两条路独立, `FPXSDKLoad` 走的是**另一套**登录入口 | 同上 |

**A 的可能性更大** —— 因为 `FPXSDKLoad` 有 `InitSDK` / `OnFpxSdkInitialized` /
`Clear` 一整套生命周期, 而 `FPXSDKBridge` 只是个轻量桥。

如果 A 成立, 那么**转发失败的真正原因**是转发**条件**不满足 ——
最可能就是**登录回调本身没回来**(`OnVerifyCodeLoginRet` 0 次)。

### 下一步(唯一该做的事)

**反汇编 `FPXSDKLoad.OnFPXCallback` 的方法体。**

这是目前唯一能打破僵局的动作 —— 它能直接告诉我们:

1. 它到底转不转发给 `FPXSDKBridge`
2. 转发的**条件**是什么
3. 什么情况下会静默丢弃

这个动作**没人做过**(此前只挖了 FPX.dll 的字符串和 RTTI, 没碰过方法体)。
