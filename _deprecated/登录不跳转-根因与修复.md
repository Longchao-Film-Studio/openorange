# 登录不跳转 —— 根因与修复记录

## 一、结论

**找到了真正的根因：`get_config` 返回的配置值与客户端内置值不一致。**

这不只影响显示，而是 **FPX SDK 的签名密钥不匹配** —— 客户端用内置的
`app_secret` / `api_secret` 给请求签名，我们返回了假值，导致 SDK 内部校验失败，
**登录成功的回调没有传递给游戏 Lua 层**，所以登录按钮恢复原状、不跳选服。

## 三、根因: 配置值不一致

### 客户端内置(`fpx_config.json`) vs 我们返回

| 字段 | 客户端内置 | 修复前我们返回 | 状态 |
|---|---|---|---|
| `app_id` | `deep.cn.prod` | `deep.cn.prod` | OK 本来就对 |
| **`app_secret`** | `5217e02b-7fce-40fd-9c4c-55db1cb349d0` | `openorange` | 已修 |
| **`channel_id`** | `mubao` | `openorange` | 已修 |
| **`sub_channel_id`** | `mubao` | `openorange` | 已修 |
| **`package_id`** | `mubao.mubao.A6mfck` | `openorange` | 已修 |
| **`fp_account.api_secret`** | `5TB163SWDgXk8jvpHyGqMkVLoiOHN30x` | `openorange` | 已修 |
| `auth.api_key` | `OkSHb2iUkYKrV9h6` | 同 | OK |
| `fp_account.api_key` | `1wTOoUwJ4FxhIsoU` | 同 | OK |

### 为什么这会导致不跳转

```
客户端 FPX SDK 内置密钥 K (来自 fpx_config.json)
        |
调用 /api/get_config
        |
服务端返回了密钥 K2 (假的, "openorange")
        |
SDK 用 K2 校验/派生后续状态 -> 与本地 K 不一致
        |
登录虽然完成(CURL 请求成功, 服务端返回 200)
但 SDK 内部状态机判定异常 -> 不触发 OnVerifyCodeLoginRet 回调
        |
C# 层收不到回调 -> Lua 层收不到 -> 登录界面不跳转
```

### 特别注意: 两个域用不同的 key

`auth` 域和 `fp_account` 域**故意使用不同的 api_key**，这不是笔误：

| 域 | api_key |
|---|---|
| `auth` (实名认证) | `OkSHb2iUkYKrV9h6` |
| `fp_account` (用户中心, **登录走这个**) | `1wTOoUwJ4FxhIsoU` |

## 四、次因: 补丁域名 l2 已下线(已自动降级, 非致命)

```
l1-prod-patch-deep.haowancheng.cn  ->  DNS 正常, 直连 200  OK
l2-prod-patch-deep.haowancheng.cn  ->  DNS 不存在          FAIL
```

游戏主用 l2，失败后自动降级 l1，**最终成功**，只是多花约 3 秒。

**另外发现**: Unity 的 `UnityWebRequest` **不读 `http_proxy` 环境变量** ——
服务端代理日志里 patch 域名出现 **0 次**，证明它一直在直连。

## 六、附带发现(不影响登录)

| 现象 | 说明 |
|---|---|
| `MapViewOfFile failed, code 5` | NEP 反作弊共享内存创建失败，权限问题 |
| `lua file:... already exist in dicts!` | Lua 模块重复注册，打包遗留 |
| `Curl error 35 ... UnityTls` | Unity 侧 libcurl 证书校验，与 FPX 无关 |
| 真实 `patch_info_release.json` 是加密二进制 | 需要 SDK 密钥解密，暂不伪造 |
