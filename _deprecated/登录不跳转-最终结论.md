# 登录不跳转 —— 最终结论(反编译取证完毕)

## 结论

> **断点在客户端的 SDK 回调分发层，不在服务端。**
>
> `FPXSDKBridge.OnFPXCallback` —— 唯一能把登录回调转发给 Lua 的函数 ——
> **在整个会话中一次都没有被调用过（连 init 都没有）。**
>
> 而 FPX.dll 的 init 回调确实产生了，只是被送到了**另一个入口** `FPXSDKLoad`。

## 二、为什么这不是服务端的问题

三点独立证据：

### 证据 1：断点在 init 阶段，早于任何网络请求

```
日志第 54 行:  Curl error 35: Cert verify failed ...        <- 第一个网络动作
日志第 55 行:  {"module":"platform","func":"init","result":{"code":1,...}}   <- init 回调
```

**`FPXSDKBridge.OnFPXCallback` 连这条 init 都没收到。**
init 是 SDK 本地初始化完成的回调，**与 fp-passport 服务器无关**。

### 证据 2：服务端数据已被 FPX 接受

| 接口 | 服务端日志 | 客户端行为 |
|---|---|---|
| `/api/send_code` | `send_code -> mobile=18888888888 code=071189`，响应 `{"code":0}` | 界面显示验证码已发送 |
| `/api/login` | `login OK mobile=18888888888 account_id=oo_f5938e982e1d3cf0` | 请求被正常解密处理 |

**如果服务端数据格式错误，`/api/login` 根本不会返回 200。**

### 证据 3：Lua 侧已准备就绪

`main.lua` 成功执行（日志第 1066 行 `Consume time:1.023861 XLuaManager.Start`，
该行只在 `lua_pcall` 成功时打印，见 `XluaManager.Start()` 第 333213 行）。

它加载了 `fpxsdkinclude.lua`，其中：

```lua
require("Modules.SDK.FPXSDKReceiver")       -- 注册全局 OnFPXCallback
FPXSDKBridge.SdkLuaApiInitialized = true   -- 打开 C# 转发开关
```

**接收端一切就绪，只是没人调用它。**

## 三、完整断点示意

```
FPX.dll 原生层
     |
     | 产生回调: {module:"platform", func:"init"/"login", result:"..."}
     v
FPXInternal.Update()   <-- FunPlus.SDK.FPX 第三方程序集
     |
     +---> FPXSDKLoad.OnFPXCallback        [日志证明: 收到了 init]
     |          |
     |          +---> 只打日志, 不转发给 Lua   <-- 断点在这里
     |
     +---> FPXSDKBridge.OnFPXCallback      [日志证明: 一次都没收到]
                |
                +---> Lua OnFPXCallback  (fpxsdkreceiver.lua:12)
                          |
                          +---> EnterGame()  (fpxsdkreceiver.lua:19)  <-- 跳转
```

**`FPX.InitCallBack` 注册的回调，被 `FPXSDKLoad` 那条路径抢占了。**

## 五、下一步（客户端侧，方向明确）

### A. 确认 `FPXSDKLoad` 与 `FPXSDKBridge` 的注册时序

`FPXSDKBridge.Init()` 在 `DeepClient.LoadGame.Start()` 里调用（热更第 333458 行）。
但日志第 54 行的 init 回调**早于** `LoadGame.Start()`（日志第 2959 行）。

```
日志顺序:
  [ 54] Curl error 35                                  <- FPX 已发网络请求
  [ 55] platform/init 回调                              <- FPX 已初始化完毕
  [2959] DeepClient.LoadGame:Start()                    <- 这里才调 FPXSDKBridge.Init()
```

**`FPXSDKBridge.Init()` 注册得太晚了 —— init 广播早已发生。**

但这解释不了 login 回调也收不到（login 发生在很晚，用户点按钮时）。
所以还需要看 `FPX.InitCallBack` 是否只保留最后一个回调。

### B. 可行的方向

| 方向 | 说明 |
|---|---|
| 让 `FPXSDKBridge.Init()` 提前 | 在 FPX 初始化**之前**注册（改 C# 或找已有钩子） |
| 让 `FPXSDKLoad` 转发 | 但它是第三方 SDK，无法修改 |
| 从 Lua 侧直接调 `FPXSDKBridge.Init()` | `fpxsdkinclude.lua` 里加一行即可，**这是最小改动** |

### C. 最值得先试的一步

`fpxsdkinclude.lua` 第 7 行已经是：

```lua
FPXSDKBridge.SdkLuaApiInitialized = true
```

在它**前面**加一行 `FPXSDKBridge.Init()`（Lua 侧已有 wrap，第 129264 行）：

```lua
FPXSDKBridge = CS.DeepClient.SDK.FPXSDKBridge
FPXSDKBridge.Init()                      -- 重新注册回调, 抢回槽位
FPXSDKBridge.SdkLuaApiInitialized = true
```

这样在 **Lua 起来时**（`main.lua` 执行）重新注册一次，
而 `main.lua` 早于用户点登录按钮，**有机会抢回回调槽位**。

> ⚠️ 注意：这需要修改**客户端 Lua 文件**（`PersistentPath/Patch/Lua/` 里的字节码），
> 属于客户端改动，与「服务端」范畴不同，需你确认是否要做。
