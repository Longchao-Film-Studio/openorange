# 登录不跳转 —— 第四次修正：SdkIsInitialized 是 true

> 全部来自 `GameAssembly_clean.dll` 反汇编 + `Player.log` 行号。

---

## 零、我的四次误判（全部作废）

| # | 我说过 | 反证 | 判定 |
|---|---|---|---|
| 1 | `FPXSDKLoad` 抢占回调槽 | `InitSDK` 不注册回调 | 错 |
| 2 | `/api/login` 字段类型不对 | 那是登录面板自己的 HTTP | 错 |
| 3 | `platform` 是 `FPXCompat` 空壳 | 日志行 59/92 有 `FPXWin`/`FPCAPI` | 错 |
| 4 | `SdkIsInitialized == false` | 该值为 false 时会 `LogWarning`，日志 0 次 | 错 |

前 3 条错因是 grep 模式不对；第 4 条错因是我把 IL2CPP 的类型初始化哨兵
（`0x031EDA62/63/65`）误当成了 `IsInitialized` 的地址。

## 一、反汇编拿到的硬证据（本轮新增）

### 1.1 `IsInitialized` 不是绝对地址，是类静态区偏移 0

```asm
FPXSDKBridge.Init  RVA 0xF5BCF0
  0x00F5BD9A  mov rcx, [0x02F658D8]        ; FPXSDKAPI 类
  0x00F5BDA1  mov rdx, [rax + 0xb8]        ; ★ rax=FPXSDKLoad, [类+0xb8]=静态字段区
  0x00F5BDAF  movzx ebx, byte ptr [rdx]     ; ★ 读 IsInitialized(偏移0)
  0x00F5BE24  mov byte ptr [rcx + 8], bl   ; 写 SdkIsInitialized(偏移8)
```

`SdkIsInitialized` 同理：`FPXSDKAPI` 静态偏移 `0x8`，**不是绝对地址**。

### 1.2 `FPXSDKAPI.Call` 的守卫是真的，且失败会打警告

```asm
FPXSDKAPI.Call  RVA 0xF5B4D0
  0x00F5B599  xor  ecx, ecx
  0x00F5B59B  call 0x87c320                 ; get_SdkIsInitialized
  0x00F5B5A0  test al, al
  0x00F5B5A2  je   0xf5b7c5                 ; ★ false 就跳
  0x00F5B5C4  call 0xf4f330                 ; 第二道检查
  0x00F5B5CB  je   0xf5b78e

  0xF5B7C5:                                 ; ★ SdkIsInitialized == false 分支
  0x00F5B7DA  mov  rcx, [0x02F4AC20]        ; 警告字符串
  0x00F5B7F2  jmp  UnityEngine.Debug$$LogWarning  ; ★ 无条件打警告
```

### 1.3 日志里该警告 = 0 次

```
SdkIsInitialized                 x0    ← 守卫失败的警告没出现
unInitialized                    x0
FPXSDKAPI.Call                   x0
FPX initialize failure           x0    ← OnFPXCallback 失败分支也没出现
FPX init success                 x3    ← 行 56/62/68
FPX sdk initialize result        x1    ← 行 74: result : 1
EnterInitCrash                   x1    ← 行 80
```

## 二、两条独立证据链证明 IsInitialized == true

### 链 A：`OnFpxSdkInitialized` 的写入点

```asm
FPXSDKLoad.OnFpxSdkInitialized  RVA 0x12CE7D0
  0x012CE860  call FPXInternal.GetPlatform()
  0x012CE886  call 0x5c40                     ; platform.Call(...)  → 成功路径
```

### 链 B：`OnFPXCallback` 的分支

```asm
FPXSDKLoad.OnFPXCallback  RVA 0x12CDEA0
  0x012CE2AE  mov rax, [0x02F65B00]           ; FPXSDKLoad 类
  0x012CE2B5  mov rcx, [rax + 0xb8]           ; 静态区
  0x012CE2BC  cmp byte ptr [rcx], 0           ; ★ if (IsInitialized == false)
  0x012CE2BF  jne 0x12ce383                   ;    true → 跳到 OnAppStartUp

  ; ---- false 分支：打错误 + 回调 false ----
  0x012CE346  call Debug.LogError             ; "FPX initialize failure!"
  0x012CE359  mov rcx, [rcx + 8]              ; OnCompletedCb
  0x012CE37C  call rax                        ; OnCompletedCb(false)

  ; ---- true 分支 ----
  0x012CE383  call FPXSDKLoad.OnAppStartUp    ; ★ 走这里
```

**日志行 80 有 `EnterInitCrash`（`OnAppStartUp` 内部打印），而行 0 次 `FPX initialize failure!`**
→ **走的是 `0x012CE383` 的 true 分支** → `IsInitialized == true`。

## 三、所以问题不在 `SdkIsInitialized`

修正后的链路：

```
main.lua:56   FPXSDKAPI.Call(PLATFORM, LOGIN, nil)
  ├─ fpxsdkapi.lua:57  SdkIsInitialized 检查      → true，通过 ✅
  ├─ FPXSDKAPI.Call (0xF5B4D0) 守卫               → true，通过 ✅
  │    0x00F5B5A2  je 0xf5b7c5 没跳              (日志无警告)
  ├─ FPX.CallNew (0x12CFB60)
  │    0x012CFBBF  je 0x12CFBF2  没跳            (platform 非 null)
  │    0x012CFBDD  call 0x5C40   platform.Call(...)  ← 这里
  └─ FPXWin.Call (0x12CF740) → jmp FPCAPI.Call (0x128dac0)
       └─ 应该转发到 FPCWindows.Login
```

**断点收窄到：`FPCAPI.Call` 的 module/func 分派表里没有匹配到 login，或 `FPCWindows.Login` 被调但无日志。**

## 四、`FPCAPI.Call` 的结构（本轮反汇编）

`FPCAPI.Call` RVA `0x128dac0` 开头是**极长的字符串表**（约 100+ 条 `lea rcx,[...]` + `call 0x2a0a30`），
这些是 IL2CPP 的 `Il2CppCodeGenModule` 字符串初始化，之后才是真正逻辑。
